# Общая база данных (Supabase) для PetroTransit

Что становится общим: объявления, статусы маршрутов, расписание и правки справочника маршрутов. Читать данные может любой посетитель, менять — только диспетчеры с логином.

1. Создайте бесплатный проект на https://supabase.com (регион ближе к Казахстану, например Frankfurt).
2. SQL Editor → New query → вставьте содержимое `supabase_setup.sql` → Run.
3. Authentication → Sign In / Providers → Email: **отключите «Allow new users to sign up»** (иначе любой сможет зарегистрироваться и получить права записи).
4. Authentication → Users → Add user → создайте каждого диспетчера (email + пароль, отметьте «Auto Confirm User»).
5. Project Settings → API: скопируйте **Project URL** и ключ **anon / public** в `config.js`:
   `window.PT_CONFIG={supabaseUrl:'https://XXXX.supabase.co',anonKey:'eyJ...'};`
6. Выложите все файлы на хостинг по HTTPS (GitHub Pages, Netlify, Cloudflare Pages).
7. Откройте приложение → «Диспетчерская»: появится вход по email и паролю. Внизу экрана входа видно, в каком режиме работает приложение.

Важно:
- Ключ `service_role` в `config.js` никогда не размещайте — только `anon`.
- Если два диспетчера правят одновременно, второй получит сообщение о конфликте и свежую версию.
- Пассажиры подтягивают изменения при открытии и раз в минуту.
- Резервная копия: «Экспорт JSON» в диспетчерской.


Обновление для обращений пассажиров: после замены файлов откройте Supabase → SQL Editor и выполните обновлённый `supabase_setup.sql`. Он создаст таблицу `report_submissions`: посетители смогут отправлять сообщения, а авторизованные диспетчеры — просматривать их и отмечать обработанными.

Обновление v19 (удаление обработанных обращений): снова выполните обновлённый `supabase_setup.sql` в SQL Editor. Он добавит политику, разрешающую авторизованным диспетчерам удалять только обращения со статусом `done`.

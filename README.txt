PetroTransit — расширенный городской транспортный прототип

ФУНКЦИИ:
• Тёмная карта Петропавловска на CARTO/OpenStreetMap.
• Поиск маршрутов/остановок, выбор маршрута и список остановок.
• Геокодирование остановок Photon и прокладка дорожного пути OSRM.
• Избранные маршруты сохраняются в браузере.
• Планировщик участка между остановками.
• Геолокация пользователя (только после разрешения браузера).
• Обратная связь через почтовое приложение.
• RU/KZ переключение интерфейса (часть справочных названий остаётся исходной).
• Диспетчерская панель, PWA-установка при размещении на HTTPS, базовый service worker.
• Условный traffic layer — демонстрация, НЕ реальные пробки.

ВАЖНО ДЛЯ ЗАПУСКА:
Для корректной работы геолокации, PWA и Service Worker разместите сайт на HTTPS-хостинге (например, GitHub Pages, Netlify или собственном сервере). При открытии file:// некоторые функции браузер ограничивает. Карта и внешние сервисы требуют интернет.

ДАННЫЕ И ОГРАНИЧЕНИЯ:
В базе сейчас только четыре справочных маршрута (24М, 25, 25М, 26М) и списки остановок из предыдущего учебного прототипа. Они не проверены официальным перевозчиком. Геокодер ищет координаты по названиям; результаты могут ошибаться, а OSRM строит автомобильный путь между точками, не официальную трассу автобуса.
GPS автобусов, точное расписание/ETA, реальные пробки, тарифы, уведомления и официальные маршруты не подключены. Для публичного сервиса необходимо получить/проверить GTFS, GPS/AVL API, согласование с перевозчиками/акиматом, настроить сервер, мониторинг, защиту данных и поддержку пользователей.


ДОБАВЛЕНО: ДИСПЕТЧЕРСКАЯ (без GPS)
• Демо-вход диспетчера: PIN 2468 (обязательно сменить/заменить до публичного запуска).
• Редактирование и добавление маршрутов/остановок.
• Ручные статусы маршрута: задержка, отмена, восстановление, комментарий.
• Публикация и снятие пассажирских объявлений.
• Ручной справочник расписания/интервалов.
• Пассажирская часть отображает объявления и статусы.
• Данные хранятся в localStorage этого браузера. Разные устройства/диспетчеры НЕ синхронизируются.
• Это локальная демонстрационная диспетчерская, а не защищённая система доступа. Для настоящей работы необходим backend, учётные записи/роли, серверная база, журнал действий, резервное копирование и HTTPS.

• Если диспетчер не задал расписание, используются ОРИЕНТИРОВОЧНЫЕ значения (это предположение, а не данные перевозчика): маршруты с «М» — 06:30–22:00, интервал 10 мин; обычные — 06:30–22:00, 15 мин; трёхзначные (пригородные) — 07:00–20:00, 60 мин. Пассажирам показывается пометка «ориентировочное расписание». Функция etaTT() в конце app.js. Расписание из диспетчерской всегда имеет приоритет — внесите реальные интервалы после сверки с перевозчиками.
